# EventGuard 简历描述

## 项目名称

EventGuard：电商订单事件溯源与智能异常治理平台（个人全栈项目）

## 项目描述

面向电商订单全生命周期的追溯与异常治理场景，项目将订单状态变更保存为可回放、可审计的领域事件，并结合异步读模型、异常检测、告警分析、人工补偿和运营查询，形成从问题发现到处置的闭环。

## 技术栈

Java 17、Spring Boot 3.3、PostgreSQL、Kafka、Debezium、FastAPI、Vue 3、Docker Compose、事件溯源与 CQRS。

## 核心贡献

1. 重构订单写入为事件溯源：针对状态覆盖、并发冲突和重复入账，以不可变事件记录状态，采用版本校验、唯一约束和重试兜底；以commandId、command_log和请求指纹去重，每100事件生成快照。重复提交不新增事件，重建仅回放增量

2. 完善读写分离异步读模型：针对投影重复、乱序和数据滞后，引入同事务消费去重表、版本守卫、投影提交通知、50毫秒兜底轮询和2秒超时；重复消息不重复更新，乱序不覆盖新状态，负载验收中527个写后抽样全部2秒内追平，零错误零超时

3. 搭建数据库变更捕获链路：针对数据库与消息发布双写不原子，通过Debezium读取PostgreSQL WAL并写入Kafka，消费端采用手动提交、3次重试和死信队列隔离毒消息；数据库宕机或Kafka暂停后均在2秒内恢复，已提交事件零丢失

4. 设计可降级的智能查询与处置闭环：针对LLM生成SQL的注入、超时和告警无处置，模型只做意图分类、参数抽取，查询走固定只读模板，8秒超时降级摘要；8个查询场景均正确，支付重试超限与库存失败补偿成功，高风险操作进入人工审批

5. 构建规则与模型分层的异常检测：针对模型误报高，离线叠加Isolation Forest后F1由0.887降至0.753，定位contamination失配与特征漂移根因，混合真实数据重训并持久化校准模型；校准后正常订单零误报，突发与金额尖峰类真实异常仍全部命中

6. 建立验证与可观测体系：针对故障路径无验证、线上问题难定位，搭建一键功能、负载和故障演练，接入Prometheus、Grafana和Loki覆盖命令、投影、积压、告警与补偿指标；三端338项测试通过，50写并发下吞吐70.78组/秒、错误率0%、P95为925毫秒

## 可引用数字及边界

- 在资源受限单机、关闭限流的 50 写并发实测中，系统完成 70.78 组下单加支付业务迭代每秒，写路径错误率为 0%，写路径 P95 为 925 毫秒。这是特定环境下的实测结果，不代表生产容量。
- 读己写抽样会携带目标版本并校验版本、状态和金额。在 30 写并发、关闭限流与死信重放的测试态验收中，527 个样本全部在 2 秒内追平、零 409；该结果为测试态最优，不将其表述为强一致读取。
- 离线对照中规则基线 F1 为 0.887，叠加 Isolation Forest 后为 0.753；定位特征漂移根因并混合真实数据重训校准后，演示数据正常订单零误报，真实异常仍被命中。
- 当前三端测试合计 338 项。该数字表示测试通过数量，不代表测试覆盖率。
- 项目已在单机 Docker Compose 环境完成部署和全链路验证，但没有真实生产用户或业务流量。因此不使用“生产运行”“服务 N 个用户”或“端到端精确一次”等表述。
