# EventGuard 简历描述

## 项目名称

EventGuard：电商订单事件溯源与智能异常治理平台（个人全栈项目）

## 项目描述

面向电商订单全生命周期的追溯与异常治理场景，项目将订单状态变更保存为可回放、可审计的领域事件，并结合异步读模型、异常检测、告警分析、人工补偿和运营查询，形成从问题发现到处置的闭环。

## 技术栈

Java 17、Spring Boot 3.3、PostgreSQL、Kafka、Debezium、FastAPI、Vue 3、Docker Compose、事件溯源与 CQRS。

## 核心贡献

1. 重构订单写入为事件溯源模型。以不可变事件作为订单状态的事实来源，使用聚合版本唯一约束、前置版本校验和重试处理并发冲突；通过 `commandId`、命令日志、事务内 advisory lock 和请求指纹保证顺序及并发重复命令不会重复入账，并且每 100 个事件生成快照以缩短聚合重建时间。

2. 建立异步读模型和有界读己写能力。投影消费者在同一数据库事务中完成原子去重和版本守卫，避免至少一次投递造成重复或状态倒退；写后查询可携带目标版本等待投影追平，投影提交后主动唤醒请求，并以 50 毫秒轮询兜底，超过 2 秒则明确返回同步中的状态。

3. 搭建基于 CDC 的事件分发链路。通过 Debezium 从 PostgreSQL WAL 捕获已提交的领域事件并发送至 Kafka，避免业务代码同时写数据库和发消息的双写窗口；消费者按失败重试、死信隔离和幂等处理的方式保障下游可恢复。

4. 实现规则与模型分层的异常检测。实现 5 条业务规则和 3 条流程规则，并接入 Isolation Forest 与 HMM 作为补充检测；通过基线对照发现 Isolation Forest 未提升召回率且显著增加误报，因此如实保留规则基线优于模型的结论。

5. 设计受限的智能查询和异常处置流程。自然语言查询只负责意图分类、参数抽取和结果润色，实际查询调用固定的只读模板接口而不生成 SQL；异常处置通过 Saga 编排，高风险退款和冻结操作进入人工审批。

6. 完善验证与可观测能力。建立后端、智能服务和前端测试以及一键功能、负载和故障演练；接入 Prometheus、Grafana 和 Loki，覆盖命令、投影、消费者积压、告警与补偿等关键指标。

## 可引用数字及边界

- 在资源受限单机的 30 写并发验收中，系统完成 52.39 组下单加支付业务迭代每秒，写路径错误率为 0%，写路径 P95 为 1262 毫秒。这是特定环境下的验收结果，不代表生产容量。
- 读己写抽样会携带目标版本并校验版本、状态和金额。在 157 个样本中有 110 个在 2 秒内追平，其余请求明确返回 409，不将其表述为强一致读取。
- 离线规则基线的 F1 为 0.887，叠加 Isolation Forest 后为 0.753。模型没有带来可引用的效果提升。
- 当前三端测试合计 338 项。该数字表示测试通过数量，不代表测试覆盖率。
- 项目已在单机 Docker Compose 环境完成部署和全链路验证，但没有真实生产用户或业务流量。因此不使用“生产运行”“服务 N 个用户”或“端到端精确一次”等表述。
