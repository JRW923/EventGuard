# 量化口径：哪些数字能写，哪些不能

写简历、答面试前先过一遍这页。规则很简单：**这里列为「可用」的才敢说，列为「禁用」的一个字都不要提。**

面试官追问一个编出来的数字，整场信任就没了。而承认「这个我还没测」的代价几乎是零。

## 一、可用（有实测文件支撑）

### 端到端功能评测（bench functional，2026-08-10 实测）

来源：[`eventguard-benchmark/out/benchmark-report.md`](../../eventguard-benchmark/out/benchmark-report.md)（`docker compose --profile bench run --rm bench` 一次跑出）。

**8/8 套件全 PASS，80/80 断言通过**。逐项：

| 维度 | 指标 | 实测 |
|---|---:|---|
| 事件溯源/CQRS（s01） | 读己写收敛 p50 | **507 ms**（有界轮询 50ms/2s 超时，与代码参数一致） |
| | 幂等重放 / 回放一致性 | 通过（重复提交不重复入账；13/13 断言） |
| CDC→Kafka（s02） | Debezium 捕获延迟 | p50 **697 ms** / p95 739 ms / p99 751 ms |
| | 投影收敛延迟 | p50 **3.6 ms** / p95 8.7 ms / p99 11.8 ms |
| AI 异常检测（s03） | 7 类注入全部检出 | **TP=7，FN=0**（R001 金额偏离 / R002 重复支付 / R003 状态跳跃 / R004 高频下单 / R005 库存超卖 / P002 停滞 / P003 死循环） |
| | 精确率 / 召回 / F1 | **P=0.636，R=1.0，F1=0.778** |
| | 检测延迟 | p50 **40 ms** / p95 590 ms |

| | 查询延迟 | p50 **2.67 s** / p95 5.15 s（LLM 实时生成，configured 模式） |
| Saga 补偿（s05） | 成功率 | **100%**（支付重试超限→REFUND 挂审批→审批后补偿闭环；库存失败→MARK_OUT_OF_STOCK+通知） |
| | 端到端延迟 | p50 **1.10 s** |

| RBAC（s07） | 角色×端点矩阵 + 机器密钥 + 匿名/坏 token + WS | **18/18 = 100%** |

**必须记住的诚实边界**（这些数字是**单次运行**的功能链路实测，不是压测）：

1. 上面所有延迟都是**单套件内的 p50/p95**（有界自节奏 ≤4 req/s），不是并发下的。QPS、负载下的 P99 仍在禁用区。
2. CDC 捕获延迟跨运行有方差（另一轮跑出 p50 204ms），上表取最终一版 p50 697ms——它量的是单次 commit→Kafka 落点，量级对，别当稳定值报死。
3. s03 的 precision 口径：只统计本套件 7 笔注入单 + 20 笔对照单的告警。运行日志如实记录了被排除的 25 条外部告警——全是 IsolationForest 按 5% contamination 对同用户批量订单（R001 的 10 笔基线 + R004 的 19 笔批量）判出的异常，与离线 ai-vs-baseline 评测里 IF 高误报的结论一致。**所以这个 0.778 是"注入检出 + 对照零误报"的端到端口径，和下面的离线评测是两套数字，别混。**

### 异常检测效果

来源：[`eventguard-benchmark/ai-vs-baseline.md`](../../eventguard-benchmark/ai-vs-baseline.md)

| 检测器 | Precision | Recall | F1 | FPR |
|---|---:|---:|---:|---:|
| Baseline（固定阈值规则） | 0.879 | 0.896 | **0.887** | 0.088 |
| AI-Enhanced（IsolationForest + 规则） | 0.649 | 0.896 | **0.753** | 0.345 |

混淆矩阵：Baseline TP=1278 FP=176 FN=149 TN=1824；AI-Enhanced TP=1279 FP=691 FN=148 TN=1309。

样本：正常序列 2000 + 异常序列 1427，序列级标注（一条序列含任一异常事件即判异常）。

**必须一起记住的三个事实**，否则会讲错：

1. **两者 Recall 完全相同（0.896）**。AI 的 TP 从 1278 只涨到 1279，多抓了 1 条。所以不能说「AI 提升了召回但误报变多」——AI 的召回增益基本是零。
2. **差异全部来自误报**：FP 从 176 涨到 691，多出 515 个。FPR 从 0.088 涨到 0.345。
3. **原因是 `contamination=0.05`**：IsolationForest 被强制按 5% 比例判异常，和真实分布不匹配。它划出去的那批样本里几乎没有真异常。

### 终局预测

来源：[`eventguard-benchmark/predict-eval.md`](../../eventguard-benchmark/predict-eval.md)

RandomForest，6224 训练样本，独立测试集 6206 条前缀样本（seed=7），总体准确率 **0.7096**。

分类别 F1：CLOSED 0.885 / STUCK 0.708 / REFUNDED 0.665 / CANCELLED 0.573。

被追问时注意：CANCELLED 的精确率只有 0.423，是明显短板——召回 0.887 但精确率低，说明模型倾向于把别的类别误判成 CANCELLED。

### 代码里的确定参数

这些是从代码读出来的，随时可查：

- 快照阈值：每 **100** 个事件一次
- 乐观锁冲突重试：**3** 次，线性退避
- 读己写轮询：**50ms** 间隔 / **2s** 超时
- Kafka 消费失败重试：**3** 次，退避 0.3 / 0.9 / 1.8s，超限进 DLT
- 告警环形缓冲：**100** 条
- 事件归档周期：**90** 天
- 规则引擎 HTTP 桥接超时：**2s**（可配）
- NL 查询 LLM 润色超时：**8s**（可配），前端 axios 等 10s
- 停滞检测阈值：**24h**（可配）；死循环阈值：**5** 次（可配）
- 业务规则条数：**5** 条（金额偏离 3σ / 重复支付 / 状态跳跃 / 高频下单 / 库存超卖）
- 流程级规则：**3** 条（P001 / P002 停滞 / P003 死循环）

## 二、禁用（评测套件写了，但没跑出结果）

functional 套件已解禁（见上）。**仍然禁用**的只剩三类，各自原因明确：

- ❌ QPS / 吞吐量 —— 负载套件 s09 需要关限流（`EG_RATE_LIMIT_ENABLED=false` 重启 server 再跑 `--suites load`），当前限流开启下自动 SKIPPED，从未跑出
- ❌ 负载下的 P95 / P99 / 错误率 —— 同 s09，没数据
- ❌ 混沌注入后的恢复时间 —— 韧性套件 s10 是导入宿主机 `chaos_run.sh` 的产物，还没在机器上执行过（套件本身 NOT_RUN）

**被问到时的标准答法**：

> 功能链路我全跑过并出了报告（事件溯源、CDC、检测、Saga、限流等 8 个套件 80 条断言全过）。但**吞吐和负载下的延迟**要关限流单独压，**混沌恢复**要在宿主机跑注入脚本，这两块我还没出数，所以 QPS、负载 P99、恢复时间这些我不报。

这个回答比编一个数字强得多——「功能正确性已量化」和「负载/韧性还没量化」两条边界都清楚，不越界。

**想解禁负载/韧性就跑一次**：

```bash
# 吞吐（需先关限流）：
docker compose up -d --build eventguard-server   # 设 EG_RATE_LIMIT_ENABLED=false
docker compose --profile bench run --rm bench --suites load
# 混沌恢复（宿主机执行注入脚本）：
./eventguard-benchmark/chaos_run.sh
docker compose --profile bench run --rm bench    # 导入 chaos-results.json
```

跑出来后把数字补进本文件「可用」区，简历才能写。

## 三、其他不能说的

| 别说 | 因为 |
|---|---|
| 测试覆盖率 X% | 没配 JaCoCo / coverage，没测过 |
| 服务了 N 个用户 / 日均 N 单 | 个人项目，无真实流量 |
| 性能提升了 N% | 没有优化前的基线数据 |
| 「AI 检测准确率 88.7%」 | 0.887 是 **Baseline 规则**的 F1，不是 AI 的。AI 是 0.753，端到端 s03 是 0.778——**三套口径**，张冠李戴会被当场戳穿。面试说 F1 前先说明是哪套：离线评测（0.753）测的是序列级判异常，s03（0.778）测的是 7 类注入逐单检出 |
| 上线运行 / 生产环境 | 有部署方案文档，但没有真实生产流量。说「部署过」可以，说「生产运行」不行 |

最后一条尤其注意：项目**可以**说「已部署可访问」（Cloudflare Tunnel 方案是真的），但不能暗示有真实用户和业务量。
